# 原生互斥路线与玩家提案

本地整合分支的 R7 后续功能。旧 Adventure graph-v2 entity schema 1 保留「满足条件的分支全部开放」语义，不自动迁移既有包。新建互斥路线使用 graph-v2 entity schema 2，manifest schema 和 format ID 保持原契约；新包的 `@choice` 明确生成 schema 2。

## 编辑与游玩

图表单可选择并行或互斥，编辑独立的选项文字与开放条件。互斥选项必须有唯一 canonical `choice_id`、1–256 字的显示标签及已存在的目标；身份不来自翻译。切回并行明确移除 choice 字段，schema 2 不静默降级。没有选项的互斥节点无法通过审核。

游戏页面消费服务器过滤后的图。玩家只能为当前公开节点的公开选项提出自己的路线选择；提案可改选，同一玩家同一节点只保留一个。GM 能读取提案并确认队伍结果，玩家不能直接完成节点或替别人提案。提案最多 256 条，玩家投影仅返回本人提案，GM 返回全部可见提案。宏、任意代码和表达式不参与路线执行。

完成互斥节点必须显式指定已声明的 `choice_id`。未知选项、条件不满足、重复完成和旧并行节点携带 choice 均拒绝。只开放所选路线，保存 `selected_choices` 与有界历史，并清掉该节点提案。条件评估仍能看到本次原生 outcome 的 world ops；失败恢复 world、progress 和 economy before-image。存档失败也恢复这些状态，锁内重新做行动与绑定门禁。

后续游戏时间推进只重新评估已选路线，不能因为另一条 gate 后来满足而补开另一条路线。丢失、损坏或不匹配的选择记录拒绝推进。旧服务器无法理解 schema 2 时应拒绝包，不能按 schema 1 并行运行。

应用命令的权限、锁、保存和补偿由 `webui/services/adventure_commands.py` 负责；现有 gameplay service 只委托并组合 ruleset 投影。独立 callback 依赖不穿透 WebAPI 私有成员。只读投影不含 gate 内容、原始资源或秘密选项身份。

## 验证

先失败的测试证明旧 parser 和 progress 只有并行语义；修复后覆盖显式单选、未知/关闭选择零写入、旧包并行兼容、秘密选项过滤、源格式拒绝、真实 loader/save 恢复、玩家提案去重、非本人身份拒绝、存档失败恢复和后续时间推进不重开路线。相关后端 83 项通过，包含权限/回合并发门禁与既有 runtime。
