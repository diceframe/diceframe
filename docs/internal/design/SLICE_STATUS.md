## 缺口（不在本表）

缺口单独维护在 `GAP_REGISTER.md`（缺口 GAP-1–缺口 GAP-42）。分工：

- **切片**：一件要交付的工作，有任务书、验收、完成态 → 本表。
- **缺口**：一处已知的缺失，挡住谁、归哪片 → 缺口册。
- 连接方式：本表某行 🔵/⏸ 时，备注写缺口编号（如 F10A → `缺口 GAP-19`）；缺口册写归属哪片。**一处缺口只登记一次**。

## 两个结构问题的处理结果

1. **规格只在 `docs/dnd2024-s0-specs` 分支，main 没有** → 已在 `docs/internal/README.md` 写明
   入口与取用命令（`git fetch origin docs/dnd2024-s0-specs` + `S0_TASK_INDEX`）。
   没有把 32 份规格合入 main：它们描述的是尚未实现的行为，进 main 会被当成既成契约，
   而且一次 17k 行的文档 PR 无法评审。
2. **缺口册 `G` 与切片 `S0-G` 撞名** → 缺口编号已全量改为 **`GAP-n`**（`GAP-1`–`GAP-19`），
   相关任务书文件同步改名 `GAP4_*` / `GAP16_*`。约定：切片写 `S0-G2`，缺口写 `GAP-19`。
