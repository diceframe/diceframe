# 统一内容审核与文本分配

本地整合分支实现；不是已合并 main 的架构声明。

## 用户流程

冒险管理新增「文本分配导入」。粘贴文本或选择 UTF-8 Markdown/TXT，按标题拆成最多 32 个片段；逐段改标题、正文、保存目标或移除片段。目标为世界、独立世界书、角色模板、原生 Adventure。编辑后必须重新审核，勾选确认后才保存。角色正文只映射背景，规则属性保持空，不从 prose 推导 HP、AC、伤害等数值。

ReviewPlanOverview 供文本、世界书和文字剧本共用，展示全部操作与人类可读名称、高级来源/正文、引用及未解析引用。世界书冲突选项提供五种界面语言；未解析引用同时在 UI 和服务端阻断。世界书审核 token 包含完整 LorebookDraft（正文、激活配置和未知扩展），不会只校验条目名称。

文本分配创建用户内容，拒绝覆盖已有目标。冲突片段可以删除、修改角色内容以区别已存在的蓝图，或显式创建独立副本后重新审核。世界书原有导入流程仍支持显式更新、跳过、保留两份；多个同来源副本必须选明目标，不能按展示名称猜测更新哪一本。

## 所有权与身份

`ContentTextReview` 只做清洗、组合、审核与提交委托。显式依赖 World/Lorebook/CharacterCard/Adventure 的依赖对象，不接收完整 WebAPI。新路由仅调用 public facade，并在读取正文之前检查房主权限与请求大小。

世界使用 `worlds.create_imported_world` 创建 DB 和用户模板；世界书使用 `create_reviewed_lorebook` 和既有事务；角色使用独立 create-only 契约，不能调用会按签名覆盖的 save upsert；Adventure 使用原生 graph/bundle 验证及 import。模板语言由 owner 保留。外来引用和来源保存在对应的描述性 import metadata 中，不授予规则执行权。

文本目标 identity 来自来源、片段 ID 与显式副本 ID 的摘要，展示名编辑不改变身份。世界书 importer 的预览与存储共用来源计算，Book settings 的 `diceframe_import.external_id` 保存外部身份，source_digest 覆盖完整 draft。没有此 metadata 的历史 Book 保留既有身份，不进行猜测式迁移。

## 保存失败与重试

混合四种存储的批次**不是跨 SQLite/JSON/目录的全局事务**。每个 owner 独立原子保存，响应逐项报告成功与失败；遇到错误停止后续项目。首次写 owner 前先持久化 receipt，每项成功后原子更新 receipt。重试必须携带同一审核 token 与同一 draft，跳过已记录的成功项；未知 receipt schema、替换正文、引用缺口和目录冲突均拒绝。

UI 开始保存后冻结审核正文与目标，保持窗口可重试相同请求。成功资源已写入但 receipt 写入失败时，响应明确要求查看已保存的内容库，界面阻止自动重试。进程恰好在 owner 成功与 receipt 持久化之间退出时，稳定目标 ID 的 create-only 检查也会拒绝覆盖或重复创建；需要检查目标库，不宣称可以无条件自动恢复。未实现重开窗口后的自动查找未完成批次。

## 验证

- 先复现并修复：未解析引用仍可导入、正文替换仍接受旧 token、来源不一致导致重复检测失败、v3 语言丢失、receipt 失败重复报告一项。
- 真 owner 集成测试覆盖四目标、正文编辑、空规则属性、引用阻断、重复选项、副本、部分失败与重试、future receipt、保存后 receipt 失败。
- 房主路由权限在解析非法正文前拦截；真实 HTTP 保存后核查 DB。
- 桌面与手机 Playwright 完成四目标编辑、重新审核、保存、库读取和刷新后 Adventure 可见；检查无水平溢出，并检查截图。
