# S0-MM3 调研：SRD 5.2.1 全部怪物的特质与动作

| 项 | 值 |
|---|---|
| 数据源 | open5e v2，`document__key=srd-2024`，**331 条生物全量** |
| 规模 | 特质 **326** 条、动作 **989** 条（共 1315 条） |
| 目的 | 判断"复用"有多少，决定 MM3 该先做哪些机制 |

## 1. 方法：三层，而不是两层

用户要区分"文本严格一致"与"语义类似"。直接比字符串会得出**错误的悲观结论**，因为 SRD 把生物名词写进了句子里：

- `The dragon can breathe air and water.`
- `The devil can breathe air and water.`

这两句是**同一个机制**，字面却不相等。所以先做一步**主语归一**：把该生物的名字、类型名、子类型名替换成 `{S}`。

三层定义：

| 层 | 定义 | 用途 |
|---|---|---|
| **A 严格一致** | 主语归一后**逐字相同** | 一个模板代码覆盖一组 |
| **B 模板一致、参数不同** | 主语归一后仍不同，但把数字/骰面抽象成 `{N}` `{DICE}` 后相同 | 同一个机制，参数进数据 |
| **C 独有** | 上述都不成立 | 每个生物自己的机制 |

## 2. 结果

| | 条目 | 不同文本 | A（严格一致） | B（仅参数不同） | C（独有） |
|---|---|---|---|---|---|
| **特质** | 326 | 253 | **29 组 / 210 条（64%）** | 5 组 / 11 条（3%） | **105 条（32%）** |
| **动作** | 989 | 903 | **61 组 / 187 条（19%）** | 79 组 / 324 条（33%） | **478 条（48%）** |

**不做主语归一时**的字面严格一致只有：特质 24 组 / 97 条（30%），动作 49 组 / 135 条（14%）。
也就是说：**字面复用率被生物名词压掉了一半以上**，这是本调研最重要的一条发现。

## 3. 实现量：不是 1315 条，是 174 个模板

把 A 与 B 合并成"可参数化模板"：

| | 模板数 | 覆盖条目 | 覆盖率 |
|---|---|---|---|
| 特质 | 34 | 221 / 326 | 68% |
| 动作 | 140 | 511 / 989 | 52% |
| 合计 | **174** | **732 / 1315** | **56%** |

剩下 583 条（44%）是真正独有的机制。

## 4. A 层里最值钱的模板（按覆盖条数）

**特质**

| 模板 | 条数 |
|---|---|
| Magic Resistance | 33 |
| Amphibious | 31 |
| Pack Tactics | 17 |
| Legendary Resistance（3/日，巢穴 4/日） | 15 |
| Spider Climb | 13 |
| Legendary Resistance（4/日，巢穴 5/日） | 12 |
| Water Breathing | 8 |
| Diabolical Restoration | 6 |
| Flyby | 6 |
| Demonic Restoration | 5 |
| Sunlight Sensitivity | 5 |
| Amorphous | 4 |

**动作**

| 模板 | 条数 |
|---|---|
| Pounce（移动半速 + 一次 Rend） | 17 |
| Multiattack「两次 Rend」 | 15 |
| Multiattack「三次 Rend」 | 10 |
| Multiattack「两次 Bite」 | 8 |
| Nimble Escape（撤离或躲藏） | 6 |
| Leap（花 10 尺移动跳 30 尺） | 4 |
| Multiattack「两次 Slam / Claw / Fist」 | 4+4+3 |

**多攻击是参数化的**：`Multiattack` 有 111 种不同文本，但结构只有一种——"做 N 次攻击 X"。它是 B 层的典型，而不是 111 个独有机制。

## 5. B 层的形状

B 层 = 同一个句子骨架 + 三处变量：

1. **次数**：two / three / four
2. **攻击名**：Rend / Bite / Claw / Slam / Fist / Slash
3. **数值**：攻击加值、骰面、DC、距离

三类变量都天然是数据，不需要为每个生物写分支。

## 6. C 层是什么

C 层 583 条里，占比最大的几类：

| 类别 | 说明 | 例子 |
|---|---|---|
| **Spellcasting**（46 条动作） | 每条列出不同的法术清单与施法属性 | 龙、恶魔、法师型敌人 |
| **Shape-Shift**（13 条特质） | 变形/伪装，机制与 S0-F25 同源 | 德鲁伊型、变形怪 |
| **区域/光环类**（Fire Aura、Corrosive Form、Swarm） | 每回合的范围效果 | Fire Elemental、Gray Ooze、各类 Swarm |
| **一次性爆发**（Death Burst、Bloodied Fury、Berserk） | 触发条件各异 | Magmin、各类狂暴单位 |

这些是 MM3 之后逐条落的部分，且其中**Spellcasting 与 Shape-Shift 各自都是独立的原语**（前者要"用怪物自己的施法属性施法"，后者与 F25 共用面板合成）。

## 7. 建议的 MM3 顺序

```
MM3a  A 层特质模板（29 组，覆盖 210 条）
      └─ 多为被动：抗魔、两栖、集群战术、传奇抗性、蛛行、飞行经过
MM3b  A 层动作模板（61 组，覆盖 187 条）
      └─ Pounce / Nimble Escape / Leap / 若干固定参数攻击
MM3c  B 层参数化（Multiattack 111 种、攻击 20+ 种）
      └─ "做 N 次攻击 X" + 攻击数值进数据
MM3d  C 层按类别推进
      └─ Spellcasting（独立原语）→ Shape-Shift（与 F25 共用）→ 光环/爆发
```

**MM3a + MM3b 就能让 210 + 187 = 397 条（30%）真正可用**，而且它们大多是"被动事实"，不依赖动作经济。

## 8. 与 F25 的关系

F25 的形态缺攻击，等的是 **MM3b/MM3c**：

- `Pounce`（17 条）本身就是"移动半速 + 一次攻击"，与 F25 的附带移动机制结构相同；
- `Multiattack` 是野兽战斗力的主体（狼、熊、鲨鱼都是两击）；
- 没有这两块，变形后"能打"是假的。

## 9. 未决

1. **主语归一是否该进实现**：如果模板代码要按"生物类型"分支，就会重蹈"每个怪物一个字段"的老路；建议模板只吃参数，不吃主语。
2. **`Legendary Resistance` 需要"每日次数"资源**，与 F25 的 Archdruid 恢复共用一套 usage 机制。
3. **`Spellcasting` 的 46 条**是否值得建"怪物施法"原语，还是先允许 GM 手填法术列表——需要单独调研。
